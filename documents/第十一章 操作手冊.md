# 第十一章 操作手冊

## 11-1 系統架構與核心元件職責

本系統採用前後端完全分離之現代化微服務設計架構，各元件間職責分明且具高度解耦性，主要由以下五大核心元件協同運作：

1. **前端行動應用 (Android Mobile App)**
   - **技術堆疊**：Kotlin、Android SDK (API 26~34)、ViewBinding、CameraX、Retrofit2、Glide、Material Design。
   - **職責職能**：提供直覺式農友操作介面，支援相機即時對焦拍攝、相簿影像選取、診斷結果即時視覺化展示、置信度與免責聲明呈現、個人植物日誌管理、備忘記事編輯 (UC-08) 及誤判糾錯回饋提報。
2. **後端服務引擎 (FastAPI Backend)**
   - **技術堆疊**：Python 3.11、FastAPI 框架、SQLAlchemy 2.0、Pydantic v2、Alembic、Uvicorn。
   - **職責職能**：擔任系統調度中樞，負責 RESTful API 路由分發、JWT 權限身分鑑權、SMTP 信箱驗證與警報寄發、影像前置檢驗、雙層 AI 診斷排程、三方仲裁器決策、資料庫事務處理與 FAISS 向量檢索。
3. **資料庫持久化系統 (MySQL 8.0 / SQLite)**
   - **技術堆疊**：MySQL 8.0 InnoDB 引擎、SQLAlchemy ORM、Alembic 資料庫版本控制庫。
   - **職責職能**：保存結構化業務資料，包含使用者帳號與 Argon2 密碼雜湊、一次性權杖、官方作物病蟲害基礎資料庫、植物診斷日誌快照、Webcam 視訊警報紀錄及使用者糾錯回饋表。實體影像儲存於後端靜態目錄（`static/uploads/` 與 `static/feedback_uploads/`）。
4. **雙層 AI 協同診斷引擎 (Local ConvNeXt + Cloud Gemini)**
   - **技術堆疊**：本地 PyTorch ConvNeXt-Tiny + 雲端 Google Gemini 1.5/2.0 Flash + 三方仲裁器 (Tripartite Arbiter)。
   - **職責職能**：提供階層式推論。第一層由本地 ConvNeXt-Tiny 模型進行毫秒級（<500ms）常見 15 類病害快篩；若置信度不足或判定為複雜病害，則降級至第二層 Gemini 多模態雲端大模型進行深層辨析；最後由三方仲裁器綜合模型判定、地面真值與語意特徵裁決，徹底杜絕單一模型盲點與大模型幻覺。
5. **檢索增強向量知識庫 (FAISS RAG Knowledge Base)**
   - **技術堆疊**：FAISS 密集特徵向量庫、農業部官方病蟲害專書文本庫（`data.json`）、Google Text-Embedding。
   - **職責職能**：儲存標準病斑特徵與官方防治處方向量。當診斷命中特定病害時，自動檢索相似度最高之權威農業部文獻，將防護處置建議精準注入診斷報告，提供具備可追溯來源依據之農業防護對策。

## 11-2 系統安裝與環境設定

### 11-2-1 前置軟硬體環境需求
- **作業系統**：Windows 10/11、Ubuntu 22.04 LTS 或 macOS Monterey 以上。
- **後端環境**：Python 3.10 或 3.11、MySQL 8.0 資料庫伺服器、Git 版本控制工具。
- **前端環境**：Android Studio Ladybug (2024.2+) 或更高版本、JDK 17、Android SDK Platform 34。
- **容器環境（可選）**：Docker Desktop 或 Docker Engine 24+ 及 Docker Compose v2+。
- **金鑰與憑證**：Google Gemini API Key、Gmail 應用程式密碼（用於 SMTP 寄發驗證信與警報通知）。

### 11-2-2 步驟 1：取得專案原始碼
打開終端機（PowerShell 或 Bash），使用 Git 指令將專案儲存庫複製至本地端，並切換至專案根目錄：

```bash
git clone https://github.com/11436022/plant.git
cd plant
```

### 11-2-3 步驟 2：建立 Python 虛擬環境並安裝相依套件
為避免套件版本衝突，強烈建議建立專用的 Python 虛擬隔離環境：

```bash
# 建立虛擬環境
python -m venv venv

# 啟動虛擬環境 (Windows PowerShell)
.\venv\Scripts\activate

# 啟動虛擬環境 (Linux / macOS)
source venv/bin/activate

# 升級 pip 並安裝後端相依套件
python -m pip install --upgrade pip
pip install -r requirements.txt
```

### 11-2-4 步驟 3：配置環境變數組態檔案 (`.env`)
複製專案隨附之 `.env.example` 範本檔案並重新命名為 `.env`：

```bash
# Windows PowerShell
Copy-Item .env.example .env

# Linux / macOS
cp .env.example .env
```

使用文字編輯器開啟 `.env`，填入各項關鍵系統設定：

```dotenv
# AI 雲端服務設定
GEMINI_API_KEY=your_actual_gemini_api_key

# MySQL 資料庫連線配置
DB_HOST=127.0.0.1
DB_PORT=3306
DB_USER=plant
DB_PASSWORD=your_secure_password
DB_NAME=plant_db

# JWT 認證與安全設定
JWT_SECRET_KEY=generate_a_long_random_secret_key_at_least_32_chars
JWT_ALGORITHM=HS256
JWT_EXPIRE_MINUTES=1440

# 外部通訊與伺服器位址 (供信箱驗證與前端 App 連線)
WIFI_HOST_IP=127.0.0.1
FRONTEND_BASE_URL=http://127.0.0.1:8000
PUBLIC_BASE_URL=http://127.0.0.1:8000

# SMTP 郵件服務配置 (以 Gmail 應用程式密碼為例)
SMTP_HOST=smtp.gmail.com
SMTP_PORT=587
SMTP_USERNAME=your_gmail_account@gmail.com
SMTP_PASSWORD=your_gmail_app_password
SMTP_FROM_EMAIL=your_gmail_account@gmail.com
SMTP_FROM_NAME="Plant Doctor 智慧植栽守護團隊"
SMTP_USE_TLS=True

# 中央氣象署開放資料 API 金鑰 (選填，需至 https://opendata.cwb.gov.tw/ 申請)
CWB_API_KEY=你的中央氣象署API金鑰
```

### 11-2-5 步驟 4：本地 AI 模型權重配置
本系統採用本地與雲端雙模型架構。請確認已至 GitHub Releases 下載或備份專屬訓練權重檔：
1. 將 PyTorch 訓練權重檔 `convnext_plant_best.pth` 放置於專案根目錄。
2. 確認專案根目錄下已包含類別雙向映射字典檔案 `idx_to_class.json`。
> **備註**：若未放置本地權重檔，系統將自動啟動安全降級機制，改由雲端 Gemini 進行全權診斷，確保服務不中斷。

## 11-3 資料庫遷移與知識庫建置

### 11-3-1 步驟 1：建立 MySQL 資料庫與授權帳號
登入 MySQL 終端或管理工具，建立系統專用之資料庫實例並指派連線權限：

```sql
CREATE DATABASE plant_db CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'plant'@'%' IDENTIFIED BY 'your_secure_password';
GRANT ALL PRIVILEGES ON plant_db.* TO 'plant'@'%';
FLUSH PRIVILEGES;
```

### 11-3-2 步驟 2：執行 Alembic 資料庫版本遷移
透過 Alembic 遷移工具將最新資料庫結構（包含診斷來源快照、複核註記、Webcam 警報及使用者糾錯資料表）自動同步至 MySQL。由於專案具備多分支歷史演進，請使用 `heads`（複數）進行全分支平滑合併遷移：

```bash
# 執行遷移至最新版本 (heads)
python -m alembic upgrade heads

# 核對目前資料庫版本狀態
python -m alembic current
```

### 11-3-3 步驟 3：匯入官方農業基礎種子資料
執行種子資料匯入腳本，將農業部認證之作物類別、常見病害與常見蟲害圖鑑寫入資料庫：

```bash
python seed.py
```
> **提示**：`seed.py` 具備冪等性（Idempotent），執行時會依「作物 + 病害/蟲害」名稱更新或新增資料，不會清空或破壞既有之會員帳號與植物日誌紀錄。

### 11-3-4 步驟 4：建立 FAISS 向量知識庫與檢驗清單
執行 RAG 向量知識庫建庫腳本，將 `data.json` 農業文獻轉換為語意密集特徵向量：

```bash
python build_knowledge_base.py
```
建庫完成後，將於專案根目錄生成成對之向量索引檔案：
- `knowledge_base.faiss`：二進位密集特徵向量庫。
- `knowledge_content.json`：包含 schema_version=2、模型維度、建庫時間及各文獻出處 SHA-256 雜湊之元數據清單。
> **提示**：專案儲存庫根目錄已預載建置完成之 `knowledge_base.faiss` 與 `knowledge_content.json`，初次部署若未修改農業專書資料庫，可直接使用既有檔案，無須額外重新生成。

## 11-4 系統啟動與服務驗證

### 11-4-1 步驟 1：啟動後端 FastAPI 伺服器
於已啟動虛擬環境的專案根目錄下，執行後端啟動指令：

```bash
# 方式 A：透過專案啟動入口執行
python main.py

# 方式 B：透過 Uvicorn 伺服器掛載熱重載 (推薦開發使用)
uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
```
終端機輸出顯示 `Application startup complete.` 即代表伺服器已成功運行於 `http://0.0.0.0:8000`。

### 11-4-2 步驟 2：OpenAPI 互動式文件與健康檢查
打開瀏覽器，測試後端核心端點以確認服務健康狀態：
1. **根目錄健康檢查**：存取 `http://127.0.0.1:8000/`，應回傳 `{"message": "Plant API is running. Open /docs for the API docs."}`。
2. **Swagger API 互動文件**：存取 `http://127.0.0.1:8000/docs`，可檢視完整之 20+ 個 RESTful API 端點規格與即時測試介面。

### 11-4-3 步驟 3：管理員帳號初次建立與驗證
1. 透過 API 介面或前端註冊一個管理者電子郵件。
2. 收取驗證信並輸入 6 位數一次性驗證碼完成信箱啟用。
3. 登入 MySQL 資料庫，將該帳號的 `role` 欄位值更新為 `admin`：
   ```sql
   UPDATE user SET role = 'admin' WHERE email = 'your_admin_email@domain.com';
   ```
4. 該帳號即可具備存取管理者專屬端點與管理後台頁面之權限。

## 11-5 Docker 容器化快速部署

為簡化部署流程，本專案提供符合現代 **Docker Compose Specification** 規範之容器化配置。

### 11-5-1 容器化架構特性
- **輕量與高性能**：基於 `python:3.11-slim` 基礎映像檔，預載 OpenMP 函式庫以發揮 FAISS 向量運算最大效能。
- **高安全性**：容器內部採用非 root (`appuser`) 權限執行，防止容器逃逸安全威脅。
- **跨平台主機連線**：內建 `host-gateway` 網路映射，容器可直接以 `DB_HOST=host.docker.internal` 連線至主機 MySQL 資料庫。
- **持久化儲存保證**：主機端 `./static/uploads`（植物診斷快照）與 `./static/feedback_uploads`（糾錯回饋圖檔）自動掛載至容器，重啟或升級容器資料不遺失。

### 11-5-2 一鍵建置與啟動指令
確保 Docker Desktop 或 Docker Engine 已啟動，於專案根目錄執行：

```bash
# 建置並於背景啟動容器服務
docker compose up -d --build

# 檢查容器運行狀態
docker compose ps

# 即時檢視容器日誌輸出 (服務名稱為 web)
docker compose logs -f web

# 停止容器服務
docker compose down
```

## 11-6 Android 行動客戶端建置與連線

### 11-6-1 開發環境準備
- 使用 **Android Studio Ladybug (2024.2+)** 或更高版本開啟專案子目錄 `frontend/plantdoctor`。
- 確認 Gradle JDK 設定為 **JDK 17**。
- Android SDK 支援範圍：`minSdk = 26`（Android 8.0 Oreo），`targetSdk = 34`（Android 14）。

### 11-6-2 伺服器連線 IP 位址配置
由於 Android 裝置連線後端伺服器受到網路環境限制，需依據測試情境設定連線位址：
開啟 `app/src/main/java/com/example/plantdoctor/network/RetrofitClient.kt`，調整 `BASE_URL`：

```kotlin
// 情境 A：使用 Android Studio 內建模擬器 (Emulator)
private const val BASE_URL = "http://10.0.2.2:8000/api/v1/"

// 情境 B：使用實體 Android 手機進行 Wi-Fi 區域網路連線
// 請將 192.168.1.100 替換為電腦在區域網路中的實際 IPv4 位址
private const val BASE_URL = "http://192.168.1.100:8000/api/v1/"
```

### 11-6-3 編譯建置與部署運行
1. **執行單元契約測試**：於終端機執行 `./gradlew testDebugUnitTest`，確保 `DiagnosisContractTest` 11 項前後端契約測試全數通過。
2. **直接安裝運行**：將 Android 手機透過 USB 連線電腦並啟用「USB 偵錯模式」，或啟動內建虛擬模擬器，於 Android Studio 點擊工具列綠色執行按鈕 **Run 'app'**（或快捷鍵 `Shift + F10`），系統將自動編譯並部署安裝至裝置。

## 11-7 Web 管理後台存取與日常維護

系統提供四個主要 Web 管理後台頁面，供管理者掌握系統運行狀態、審查農友回報之誤判病斑及即時調試視訊串流：

### 11-7-1 管理後台路由導覽
管理者登入具備 `admin` 角色之帳號後，可於瀏覽器存取以下頁面：
1. **管理者儀表板 (`/dashboard`)**：
   - 網址：`http://127.0.0.1:8000/dashboard`
   - 功能：展示全站植物診斷總筆數、常見病害排行榜、今日診斷活躍趨勢圖及系統運行健康指標。
2. **診斷回饋與審核介面 (`/feedback`)**：
   - 網址：`http://127.0.0.1:8000/feedback`
   - 功能：審查農友回報之誤判個案（UC-13, UC-14），可對照原 AI 診斷、農友修正標籤與比對圖檔，作為模型後續主動學習（Active Learning）之標註依據。
3. **使用者帳號管理介面 (`/users`)**：
   - 網址：`http://127.0.0.1:8000/users`
   - 功能：查詢所有註冊會員清單、信箱驗證啟用狀態，支援手動啟用帳號或調整權限角色。
4. **Webcam 即時串流監控控制台 (`/webcam`)**：
   - 網址：`http://127.0.0.1:8000/webcam`
   - 功能：瀏覽器即時影像監控介面，支援自訂監控畫面取樣頻率、自訂劃定檢驗區域（ROI）、調整連續 3 幀共識判定門檻及防抖冷卻時間。

### 11-7-2 日常資料庫備份與知識庫更新
1. **資料庫備份**：
   建議每日透過 `mysqldump` 定時匯出備份資料：
   ```bash
   mysqldump -u plant -p plant_db > backup_plant_db_$(date +%Y%m%d).sql
   ```
2. **農業部最新病蟲害資料熱更新**：
   當農業主管機關釋出最新病蟲害公開資料時，可執行資料同步腳本更新 `data.json`，並依序重建向量庫與資料庫：
   ```bash
   # 更新農業部開放資料
   python update_reference_data.py

   # 重新建立 FAISS 向量知識庫
   python build_knowledge_base.py

   # 增量更新資料庫作物病蟲害基礎對照表
   python seed.py
   ```

### 11-7-3 團隊 Git 版本協作規範
在進行後續維護或功能擴充時，應遵循專案團隊版本控制規範：
1. **拉取最新進度**：`git pull --rebase origin main`，確保本地提交基於最新主幹。
2. **單一檔案原子化提交**：每修改一個模組或文件，單獨加入並提交，避免不同功能混雜：
   ```bash
   git add path/to/changed_file.py
   git commit -m "feat/fix: 明確的變更說明"
   git push origin <feature-branch>
   ```
