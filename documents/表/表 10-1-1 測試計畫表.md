# 表 10-1-1 測試計畫表

## 表 10-1-1 測試計畫表

為確保本植物病蟲害辨識系統在演算法精準度、即時監控可靠性、前後端資料交換契約一致性及系統資安防護之穩定運作，本系統制定涵蓋單元測試、AI階層與三方仲裁測試、Webcam防抖共識測試、RAG向量檢索測試、介面契約測試、安全與權限控制測試、端到端整合測試及效能可靠度測試等八大層級之完整測試計畫，測試策略與驗收目標如表 10-1-1 所示。

| 測試類型 | 測試方式 | 目標 |
| :--- | :--- | :--- |
| **單元測試** | 密碼安全與資料校驗：<br>1. 執行密碼雜湊與比對驗證（Argon2 / Bcrypt）。<br>2. 驗證單次驗證 Token 雜湊函式（SHA-256）產出。<br>3. 農業知識庫種子資料匯入與去重邏輯測試。 | 1. 密碼單向雜湊不可逆，校驗邏輯正確無誤。<br>2. Token 雜湊具唯一性與固定長度，符合資安標準。<br>3. 資料庫參考資料支援冪等更新，不重複寫入。 |
| **AI 階層與仲裁測試** | ConvNeXt 快篩、Gemini 雲端診斷與三方仲裁器：<br>1. 檢驗本地 ConvNeXt 權重載入與標籤雙向映射。<br>2. 測試高信心直接命中與低信心降級至雲端流程。<br>3. 驗證雙中同判定、域外作物 (OOD) 剔除、反向救援與病斑衝突仲裁。<br>4. 驗證防幻覺地面真值（Database Grounding）白名單替換。 | 1. 本地模型推論正常，高信心快篩無縫響應。<br>2. 仲裁器精準處理跨模型衝突，有效剔除未知作物。<br>3. 非官方核准之虛構病害名自動攔截，強制使用農業部專家文獻建議。 |
| **即時監控測試** | 視訊監控、防抖共識與警報機制：<br>1. 畫面幀品質檢驗（過小、全黑、無細節圖過濾）。<br>2. 連續判定共識（Temporal Consensus）模擬。<br>3. 冷卻時間（Cooldown）與 Session/Region 範圍防串擾。<br>4. 警報資料庫寫入與 SMTP 寄信非同步隔離測試。 | 1. 無效畫面直接拒絕，避免浪費伺服器推論資源。<br>2. 必須連續 3 幀判定為相同異常且具地面真值才觸發警報。<br>3. 冷卻期內不重複發信，監控會話隔離完整。<br>4. 即使郵件寄送失敗，警報紀錄與快照圖片仍持久化保存。 |
| **向量檢索測試** | FAISS 向量知識庫與檢索完整性：<br>1. 實體 FAISS 索引載入、向量比對與文字檢索。<br>2. 清單雜湊（SHA256）與向量維度校驗。<br>3. 模擬清單損毀或索引缺失情境。 | 1. 檢索正確回傳語意最相近之農業病害防治指南。<br>2. 檔案竄改或維度不符時主動拒絕載入。<br>3. 索引缺失時自動觸發安全降級，保證 API 服務不中斷。 |
| **介面契約測試** | Android 前端與後端 DTO 雙向相容：<br>1. 前端 DiagnosisContractTest 單元契約測試。<br>2. 診斷回傳 JSON 序列化與欄位保留測試。<br>3. 使用者修正備忘與原始 AI 診斷欄位隔離。<br>4. 數值邊界（NaN、Inf、極端值）與免責聲明檢驗。 | 1. 前後端資料結構契約一致，無欄位遺失。<br>2. 儲存時保留原始 AI 診斷，不被使用者筆記覆蓋。<br>3. 信心值明確標註「非準確率且非專家審核」，舊版缺少欄位時安全降級不閃退。 |
| **安全與權限測試** | 使用者認證、存取控制與防越權機制：<br>1. 未驗證信箱存取受保護端點阻擋。<br>2. 錯誤密碼與未註冊帳號統一回應（防帳號探測）。<br>3. 跨使用者存取隔離（IDOR 漏洞防範）。<br>4. 診斷暫存過期（TTL）與重複確認防護。<br>5. 管理者專屬儀表板與回饋審核端點權限阻擋。 | 1. 未驗證帳號回傳 403 / 401 拒絕存取。<br>2. 登入失敗統一口徑，不洩漏帳號是否存在。<br>3. 任何使用者無法確認或刪除他人之診斷紀錄。<br>4. 過期暫存自動作廢，重複確認回傳錯誤。<br>5. 非管理者存取管理端點直接阻擋。 |
| **功能與整合測試** | 端到端業務流程與資料庫遷移：<br>1. 完整流程：註冊 → 信箱發信/驗證 → 登入 → 拍照上傳 → AI 診斷 → 確認入庫 → 歷史查看/備忘編輯 → 登出。<br>2. Alembic 資料庫版本遷移（升級與降級）。 | 1. 全流程資料流傳遞正常，各階段資料庫寫入正確。<br>2. 圖片檔案正確保存於持久化儲存區。<br>3. Alembic 資料庫 Schema 遷移無分支衝突。 |
| **效能與可靠度測試** | API 延遲指標與高負載穩定度：<br>1. 本地 ConvNeXt-Tiny 推論延遲量測。<br>2. 雲端 Gemini + RAG 綜合推論耗時量測。<br>3. 自動化測試套件（111 題 pytest + 18 題 Node）執行耗時。 | 1. 本地快篩響應時間小於 500ms。<br>2. 雲端綜合診斷平均耗時於 3~8 秒內完成（總體上限 15 秒）。<br>3. 全套自動化回歸測試於 20 秒內全數通過。 |
