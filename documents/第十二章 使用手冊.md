# 第十二章 使用手冊

## 12-1 狀態轉換圖概覽

本系統（智慧植物病蟲害辨識與健康管理系統）採用以使用者為核心之情境驅動設計，全系統操作流程可抽象化為一系列清晰、可預測之「狀態（State）」轉換。使用者在行動端應用程式（Android App）或 Web 管理介面上的每一個「觸控／點擊操作」均會觸發特定「事件（Event）」，並推動系統在不同「畫面狀態」之間安全轉移。

系統之核心狀態機涵蓋以下六大核心畫面狀態：

1. **狀態 1：登入/註冊頁 (Unauthenticated State)**：未認證初始狀態，負責使用者身分識別、信箱驗證與密碼安全。
2. **狀態 2：應用程式主頁 (Main Dashboard State)**：已認證核心中樞，提供各項主要業務功能入口與系統連線狀態指示。
3. **狀態 3：歷史紀錄列表頁 (History List State)**：個人專屬植物健康日誌總覽，以時間軸降冪展示所有過往診斷紀錄。
4. **狀態 4：歷史紀錄詳情頁 (History Detail State)**：單筆病害深度查閱狀態，呈現高解析度病斑快照、AI 診斷標籤、官方農業防治指南與個人化備忘筆記。
5. **狀態 5：開始診斷/上傳頁 (Diagnosis Start/Upload State)**：影像採集狀態，支援 CameraX 相機即時拍照對焦與本機相簿選圖。
6. **狀態 6：診斷結果頁 (Diagnosis Result State)**：AI 多層級推論完成狀態，展示卷積快篩、Gemini 雲端辨析、三方仲裁結論、置信度與農業部文獻追溯依據。

## 12-2 畫面流程與操作說明

以下詳細定義各畫面狀態之進入條件、介面功能元件、可執行操作及狀態轉換契約：

### 12-2-1 狀態 1：登入與註冊頁 (Unauthenticated State)
- **進入條件**：
  1. 使用者首次啟動 Android 行動應用程式。
  2. 使用者於「應用程式主頁」點擊「登出」按鈕。
  3. 本地儲存之 JWT Access Token 與 Refresh Token 均過期且無法自動刷新。
- **畫面功能與安全機制**：
  - 提供帳號（電子信箱）與密碼輸入表單。
  - 提供「新用戶註冊」與「忘記密碼」專屬對話框/頁面導航。
  - 密碼傳輸均經由 TLS 加密通道，後端採用 Argon2id 演算法校驗。
- **可執行操作與狀態轉換**：
  - **登入操作**：輸入已通過信箱驗證之帳號與密碼，點擊「登入」。
    - ➡️ **成功**：系統驗證成功並於本機加密安全儲存 Token，轉換至 **狀態 2：應用程式主頁**。
    - ➡️ **失敗**：密碼不符或帳號不存在，系統統一口徑提示「帳號或密碼錯誤」，停留在 **狀態 1**。
  - **註冊操作**：點擊「註冊帳號」，填入使用者名稱、有效電子信箱及合規密碼後提交。
    - ➡️ **回饋**：後端寄送啟用驗證信，前端跳轉驗證提醒對話框。使用者須前往信箱點擊啟用連結方可正式登入。
  - **忘記密碼操作**：點擊「忘記密碼」，輸入註冊信箱。後端生成時效性單次重設權杖（15 分鐘有效期）並寄出安全重設郵件。

### 12-2-2 狀態 2：應用程式主頁 (Main Dashboard State)
- **進入條件**：
  1. 使用者通過身分鑑權成功登入。
  2. 使用者於其他子頁面（歷史清單、診斷結果頁）點擊「返回主頁」。
- **畫面功能與介面元件**：
  - 頂部導覽列：展示目前登入之使用者暱稱、頭像及連線伺服器健康狀態燈號。
  - 核心功能大卡片：
    - 「📸 即時病害診斷」：醒目主按鈕，引導進入影像辨識流程。
    - 「📖 植物健康日誌」：快速查閱歷史病害紀錄與追蹤病況發展。
    - 「🔍 農業百科知識庫」：隨時檢索官方推薦之病蟲害特徵與用藥指南。
  - 系統功能區：包含「連線設定（自訂後端伺服器 IP）」與「帳號安全登出」。
- **可執行操作與狀態轉換**：
  - 點擊「📸 即時病害診斷」按鈕 ➡️ 轉換至 **狀態 5：開始診斷/上傳頁**。
  - 點擊「📖 植物健康日誌」按鈕 ➡️ 轉換至 **狀態 3：歷史紀錄列表頁**。
  - 點擊「登出」按鈕 ➡️ 清除本機 Token 快取，轉換至 **狀態 1：登入/註冊頁**。

### 12-2-3 狀態 3：歷史紀錄列表頁 (History List State)
- **進入條件**：
  - 於「應用程式主頁」點擊「植物健康日誌」。
  - 於「歷史紀錄詳情頁」點擊頂部返回按鈕。
- **畫面功能與介面元件**：
  - 採用 RecyclerView 列表結構，依日誌建立時間進行降冪排序（最新診斷置頂）。
  - 各清單項目卡片包含：病斑縮圖、作物類別（如番茄、馬鈴薯、玉米）、判定病害名稱、診斷時間戳記及狀態標籤（「正常健康」、「確診感染」或「需專家複核」）。
  - 提供下拉刷新（Swipe-to-Refresh）手勢，自動向後端 `/api/v1/diaries` 同步最新資料。
- **可執行操作與狀態轉換**：
  - 點擊清單中任一筆病害紀錄卡片 ➡️ 帶入該紀錄之 UUID，轉換至 **狀態 4：歷史紀錄詳情頁**。
  - 點擊頂部返回箭頭 ➡️ 轉換至 **狀態 2：應用程式主頁**。

### 12-2-4 狀態 4：歷史紀錄詳情頁 (History Detail State)
- **進入條件**：
  - 於「歷史紀錄列表頁」點擊特定紀錄卡片進入。
- **畫面功能與介面元件**：
  - 高解析度影像檢視區：完整呈現診斷時拍攝或上傳之原始植株病斑圖片，支援手勢雙指縮放檢視細節。
  - AI 診斷判讀面板：
    - 診斷結果標題與雙向映射標籤。
    - 置信度進度條（Confidence Score）與三方仲裁器裁決註記。
    - 若信心度低於門檻，顯著標註「需專業人員複核」黃色警示徽章。
  - 權威防護指引（RAG 知識檢索內容）：
    - 展現從 FAISS 向量庫匹配之農業部官方防治處方，包含非化學物理防治與核准用藥規範。
    - 清楚標註引述文獻出處與可追溯依據。
  - 使用者備忘記事區 (UC-08)：
    - 提供使用者輸入欄，支援隨時追加實體用藥進度、修剪紀錄或病情好轉追蹤筆記。
- **可執行操作與狀態轉換**：
  - 編輯備忘筆記並點擊「儲存更正」➡️ 發送更新請求，成功後跳出儲存提示並更新本機快取。
  - 點擊「刪除此紀錄」➡️ 彈出二次確認對話框，確認後向後端發出刪除請求並返回 **狀態 3：歷史紀錄列表頁**。
  - 點擊頂部返回按鈕 ➡️ 轉換至 **狀態 3：歷史紀錄列表頁**。

### 12-2-5 狀態 5：開始診斷/上傳頁 (Diagnosis Start/Upload State)
- **進入條件**：
  - 於「應用程式主頁」點擊「📸 即時病害診斷」。
- **畫面功能與介面元件**：
  - 雙操作模式選擇面板：
    - 「啟動相機拍攝」：呼叫 Android CameraX 架構，具備自動對焦與中心十字輔助取景框。
    - 「從相簿選取照片」：呼叫系統安全相簿選取工具（Photo Picker）。
  - 影像預覽窗格：選取照片後即時預覽，提供旋轉與重拍功能。
  - 拍攝指引提示：提醒農友「請在充足光線下拍攝、聚焦單一病斑葉片、避免背景雜草干擾」。
- **可執行操作與狀態轉換**：
  - 完成照片選取並確認清晰後，點擊「開始 AI 智慧診斷」：
    - ➡️ 前端啟動全螢幕半透明載入動畫（Loading Spinner）。
    - ➡️ 背景協同發送多部件表單（Multipart Form）上傳圖檔至後端 `/api/v1/diaries/predict`。
    - ➡️ 診斷完成後自動切換至 **狀態 6：診斷結果頁**。
  - 點擊「取消」或返回鍵 ➡️ 中止操作，安全轉換回 **狀態 2：應用程式主頁**。

### 12-2-6 狀態 6：診斷結果頁 (Diagnosis Result State)
- **進入條件**：
  - 於「開始診斷/上傳頁」提交影像，經後端雙層 AI 與三方仲裁器運算完畢並成功接收回應。
- **畫面功能與介面元件**：
  - 診斷摘要卡片：
    - 識別作物與病害名稱（中英文對照）。
    - 綜合信心指數儀表（0% ~ 100%）。
    - AI 推論路徑標籤（「本地 ConvNeXt 高速快篩命中」或「雲端 Gemini 專家多模態辨析」）。
  - 農業部官方防治指南：自動列出 RAG 向量知識庫推薦之處理方案（病徵描述、有機處置、化學防治）。
  - 法律與專業免責聲明：明列「本系統 AI 診斷結果僅供農業管理決策參考，重大疫情請依農改場專業人員鑑定為準」。
  - 儲存至日誌按鈕區：包含「儲存並記入植物日誌」與「略過不儲存」。
  - 誤判回饋提報入口：若農友發現辨識不符，可點擊「回報診斷異常」，上傳專家正確標籤協助系統優化。
- **可執行操作與狀態轉換**：
  - 輸入備忘筆記並點擊「儲存至植物日誌」➡️ 呼叫後端 `/api/v1/diaries/confirm` 將快照與診斷持久化儲存，跳轉至 **狀態 2：應用程式主頁**。
  - 點擊「回饋誤判」➡️ 展開糾錯表單，填寫正確作物與病害名稱後上傳，協助模型收集重訓樣本。
  - 點擊「返回主頁」➡️ 捨棄本次暫存快照，安全轉換回 **狀態 2：應用程式主頁**。

## 12-3 核心功能情境操作與展示腳本

為確保評審委員會及系統使用者能迅速驗證各項功能之可靠性與健壯性，本手冊制定三大核心情境腳本：

### 12-3-1 情境一：標準端到端病害診斷流程
- **展示目的**：驗證農友自註冊登入、拍照、雙模型快篩辨析至日誌存檔之完整工作流程。
- **操作步驟**：
  1. 開啟 App，輸入認證帳號登入系統。
  2. 於主頁點擊「即時病害診斷」，點選「啟動相機」，對準患有早疫病之番茄葉片拍攝清晰照片。
  3. 檢視預覽影像無誤後，點擊「開始 AI 智慧診斷」。
  4. 系統於 1 秒內回傳診斷報告，顯示作物為「番茄 (Tomato)」、病害為「早疫病 (Early Blight)」、信心值 96.8%。
  5. 閱讀下方農業部文獻之防治措施建議，於備忘欄輸入「已噴灑波爾多液防治」，點擊「確認儲存至日誌」。
  6. 導向主頁後點擊「植物健康日誌」，確認該筆紀錄已出現在歷史清單頂部。
- **查核證據**：後端 HTTP 200 紀錄、MySQL `plant_diary` 新增一筆完整紀錄，靜態圖片保存於 `./static/uploads/`。

### 12-3-2 情境二：低信心爭議病斑與域外作物 (OOD) 處置展示
- **展示目的**：驗證三方仲裁器防幻覺機制與安全降級保護。
- **操作步驟**：
  1. 於診斷頁面上傳非支援之域外作物（例如草莓葉片）或嚴重反光之爭議病斑照片。
  2. 點擊「開始 AI 智慧診斷」。
  3. 系統偵測到邊緣卷積模型信心度低於門檻，自動調用第二層雲端 Gemini 模型進行深度特徵比對。
  4. 三方仲裁器裁決兩模型特徵衝突且作物超出支援類別，拒絕給出武斷結論，回傳「無法明確判定（Unknown）／建議採樣送檢」。
  5. 結果頁面呈現黃色「需專業人員複核」警告標誌，並引導使用者重新拍攝或採樣聯絡農改場。
- **查核證據**：仲裁器日誌輸出 OOD 救援紀錄，系統不產生偽陰性或高信心誤判。

### 12-3-3 情境三：Webcam 智慧監控串流與連續異常自動警報
- **展示目的**：驗證即時監控連續 3 幀防抖共識與非同步郵件警報架構。
- **操作步驟**：
  1. 於實驗室環境啟動 Webcam 視訊監控工作階段（Session）。
  2. 將健康植株置於鏡頭前，系統背景推論維持「正常健康」，連續異常計數（Streak）維持為 0。
  3. 將受感染植株移入取景框：
     - 第 1 幀異常：Streak = 1，持續監控，不觸發警報（防止瞬間光影雜訊）。
     - 第 2 幀異常：Streak = 2，持續監控。
     - 第 3 幀異常：Streak = 3，達成「連續 3 幀相同異常共識」。
  4. 系統立即觸發自動警報事務：
     - 將異常現場快照存入硬碟。
     - 於資料庫新增警報紀錄。
     - 非同步透過 SMTP 伺服器寄發緊急預警信至農友信箱，信中附帶病害標籤與快照截圖。
- **查核證據**：使用者電子信箱於數秒內收到「植物健康警報通知」郵件，後端日誌無阻塞現象。

## 12-4 Web 管理者後台日常維運使用指南

針對農場管理者與技術維運人員，系統提供專屬之 Web 管理者儀表板：

### 12-4-1 管理者登入與權限鑑權
1. 開啟瀏覽器存取 `http://<伺服器IP>:8000/admin/login`。
2. 輸入具備系統管理權限（`is_admin=True`）之電子郵件與密碼登入。
3. 系統簽發 HttpOnly Cookie，未授權之一通用戶無法存取後台端點。

### 12-4-2 管理儀表板與全域監控
- **診斷量能統計**：圖表化呈現每日診斷總次數、病害分佈圓餅圖及高風險染病區域警示。
- **系統資源監控**：顯示後端伺服器 CPU、記憶體佔用率及 PyTorch 模型推論平均耗時。

### 12-4-3 使用者糾錯回饋審查與模型進化
- **審查清單**：瀏覽農友透過 App 提報之誤判回饋案例，對照原始影像、AI 預測標籤與農友主張之真值。
- **樣本標註與匯出**：管理者確認無誤後，可一鍵點選「核准並納入重訓樣本庫」，系統自動將該影像與修正標籤打包存入待訓練資料集，作為後續 ConvNeXt 模型週期性微調（Fine-tuning）之訓練原料。

### 12-4-4 資料庫備份與知識庫更新操作
- **日常備份**：管理者可於後台「系統維護」分頁點選「執行資料庫即時快照」，系統將自動執行 MySQL 邏輯備份並歸檔於安全備份目錄。
- **知識庫熱更新**：當農業部釋出最新病蟲害防治專書時，上傳更新後之 `data.json` 並點選「重新建立向量索引」，系統於背景重新生成 FAISS 索引檔，無須重啟伺服器即可完成無縫熱更新。
